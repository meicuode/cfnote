# 生产验证核对表

**活文档，覆盖到 P18。** 这份表把 P13.7 起积压的验证点合并成一次能跑完的流程。

## 为什么要有这份表

积压到第 10 批的时候，最贵的不是"没验"，是**故障定位会归错帐**。P16.1 / P16.5 系列动了笔记本结构和可见性，P14.1 / P14.2 动了删除语义和备份——如果 P14.1 的删除语义其实有问题，症状现在会以"私密笔记本表现怪"的形式出现，而人会往最近那批上找。一次验完，锅才落得准。

## 这份表**不**验什么

**已被自动化测试覆盖的一律不进。** 回收站语义、备份导出导入往返、私密不变式的四条写入路径、限流窗口算术、单页不进文章流、slug 路由注册——这些在 workerd + 真 D1 + 真 R2 里跑过（`tests/worker/`，见 `README.md`「测试」一节），手点一遍只是重复劳动。

留在这里的只有测试**够不着**的三类：

| 类别 | 为什么测不到 |
|---|---|
| 真浏览器行为 | 文件选择、拖拽、右键落点、窄屏布局——没有 `@testing-library/react`，`FileList` 的活引用行为更是只有 Blink 里才有 |
| 真绑定 | Vectorize / Workers AI / Cache API / R2 + cron——`wrangler.test.toml` 刻意不声明它们（无本地实现） |
| 真部署配置 | `run_worker_first`、预渲染 HTML、`[assets]`——测试配置刻意不声明 `[assets]`，否则测试就依赖 `dist/` 构建产物 |

## 用法

- 生产地址 `https://cfnote.zuichu.de`，**先硬刷新**（Ctrl+Shift+R）。
- 第 0 步建一个专用笔记本，全程在它里面做，最后整本删掉——**不要拿真实笔记验**。
- 需要"访客视角"的地方一律开**无痕窗口**。自己登录着看什么都正常，这正是 P14.2 那个 bug 藏得住的原因。
- ⚠️ 标记的项有副作用，看清楚再做。
- 每项后面的 `(Pxx)` 是它覆盖的批次，出问题时照这个去 `DESIGN.md` §10 查当初的设计意图。

## B. 保存与编辑

- [ ] **2.** 新建一篇笔记，打一行字，**在打完最后一个字的 3 秒内连按 Ctrl+S 三次** → 列表里只多出**一篇**。
  > 这是 P15.3 的原始复现路径。主犯是自动保存定时器（打完字排下 3 秒倒计时）而不是 Ctrl+S 本身，所以**必须在 3 秒内按**，等久了测不出来。 `(P15.3)`
- [ ] **3.** DevTools 切 Offline，改动这篇笔记 → 状态栏走到「保存失败，点『保存』重试」并**停下来**（不再每 3 秒打接口，看 Network 面板确认）。恢复网络，改一个字 → 重试额度归零，能存上。 `(P15.3)`

  > 选中的那层文件夹**自己不建笔记本**，它根目录下的文档直接进当前笔记本。 `(P16.4)`
- [ ] **4b.** ⚠️ 关键一条：**先在侧栏点进一个子笔记本**（比如第 0 步建的 `子A`），再导入一个文件夹 → 东西必须进 `子A` 下面，**根上不该多出一本叫 `子A` 的笔记本**。
  > P16.3.1 换成按完整路径匹配之后，前端如果只发笔记本名字不发祖先链，就会在根上另建一本同名的，导入的文件全进那本。不丢数据但落点是错的，而侧栏只是多一本同名笔记本，**不盯着看根本发现不了**。P16.4 一并修了。 `(P16.4 修 P16.3.1)`
- [ ] **4c.** 造一个「两个子目录里各放一份**内容完全相同**的 `README.md`」的文件夹再导入 → **两篇都要进来**（各在自己那本里），底部不该报「跳过 2 篇」。
  > 建树之后标题都变回 `README`，去重键少了笔记本这一项的话第二份会被判重丢掉。 `(P16.4)`
- [ ] **4d.** **取消**勾选「保留文件夹结构」，导入同一个文件夹 → 退回老行为：全部平铺进当前笔记本，子目录里的文档标题带相对路径（`子目录/文件名`）。 `(P15.4 / P16.4)`
- [ ] **5.** 再选**单个 .md 文件**导入 → 也能进（同一个 `FileList` 活引用 bug 会同时影响单选）。导完在搜索框搜这篇的正文关键词 → **能搜到**。
  > 后半句验的是 Vectorize + Workers AI 绑定在生产真的通——本地测试环境根本没有这两个绑定。 `(P15.4 / 绑定)`
- [ ] **5b.** 导一个**几百个文件**的大文件夹（真实知识库最好）→ 进度条应当显示「正在导入 51-100 / 380 篇...」这样的真数字并一路走完，不是卡在一句「正在导入文章...」；中途别关页面。导完侧栏树与本地目录结构对得上。
  > 分片上传 + 真实进度是 P16.4 顺带清的旧账。这条也是唯一能看出「单请求上限」有没有被撞到的验法。
  > **导完那句结果提示要看清楚**：有「N 篇没能建立索引」就说明这几篇搜不到（超长正文、嵌入调用超额都会），去「设置 → 重建向量索引」可以重试。P16.4.1 之前这条信息是被丢掉的，只能靠"怎么搜不到"反推。 `(P16.4 / P16.4.1)`

- [ ] **6.** 把 `子B` 拖到 `子A` 下面（三层）；再试着把 `子A` 拖进 `子B` → **应被拒**（环检测）。然后把一篇笔记从 `子A` 拖到 `子B` → 两本的数字**一增一减**。
  > 数字那半句是 P16.6 的 `article_count` 重算。以前是 `±1` 增量写，漏一次就永久歪；现在是重算，所以哪怕歪了下一次写入也会自己纠正。 `(P16.1 / P16.6)`

- [ ] **6c.** 把 `子B` 改成和它同级的另一本**同名** → 输入框变琥珀色、底下出一行「同级已有一本叫…」，但**仍然能按 Enter 提交**。
  > 这是提示不是禁止：服务端没有唯一约束，重名不影响任何现有功能。它坏的是以后——导入按完整路径匹配（P16.3.1），两本同级同名算出同一条路径，落进哪一本取决于行序。 `(P17.1)`
- [ ] **7.** 删 `子A`（它下面还有 `子B`）→ 确认框应写明「将连同 1 个子笔记本、N 篇笔记一起移入回收站」，并说明 30 天可恢复、附件不动；按钮上带篇数。确认后整棵进回收站。

- [ ] **8.** 从回收站恢复 `子B`（**只恢复它，不恢复 `子A`**）→ 侧栏里 `子B` 应当回到 `子A` 下面，而不是跑到根上。
  > 这条验的是祖先链：`子A` 会作为「壳」跟着恢复，但**它自己的笔记仍留在回收站**。去回收站确认 `子A` 的笔记还在那儿。 `(P16.3)`
- [ ] **9.** 点 `子A`（它下面有 `子B`）→ 列表右上角出现「含子级」勾选框，**默认不勾**，只显示 `子A` 自己的笔记。勾上 → `子B` 里的笔记也进来了，每条下面多一行 `📁 归属路径`，标题栏的计数变成「N 篇文章 · 含子级」。
  > 再点一个**没有子笔记本**的笔记本 → 这个勾选框应当**不出现**（没有子级时它是个无意义的开关）。 `(P16.2)`
- [ ] **10.** 勾着「含子级」删一篇笔记 / 置顶一篇 → 列表刷新后**仍然是深视图**，不会悄悄退回浅视图。
  > 深浅状态挂在 `loadArticles` 的依赖上，漏一个调用点的表现就是「操作完列表突然少了一半」。 `(P16.2)`

## I. 登录限流（⚠️ 放最后，会锁 IP）

- [ ] **26.** ⚠️ **必须用手机流量（关 WiFi）做**，不要用你平时上网那条线路。
  故意输错密码 8 次 → 第 9 次变成「登录尝试过于频繁，请 15 分钟后再试」；**紧接着输正确密码 → 仍然被挡**。然后换回 WiFi，正常密码应当一次登进去。
  > 「正确密码也被挡」才是这条的重点——只有限流拦在密码校验**之前**才做得到，否则限流白做。
  > **为什么不能用自己的线路**：清账只在登录成功时发生，而被锁住就登不进去、也就清不了账，只能等 15 分钟窗口自然过期。
  > 如果第 9 次没被挡：最可能是 Cache API 在这个域名上没工作。那是**设计上的降级方向**（拿不到缓存就放行，免得把主人锁在门外），不是 bug，但要知道。 `(P16.6)`

## K. 改密码与 JWT 吊销

- [ ] **27.** 设置 → **账号**：填旧密码、新密码、再输一次 → 点「修改密码并登出其他设备」。成功后界面**不报未登录**（新 token 已自动换上），底部出绿字「密码已修改，其他设备上的登录已全部失效」。
  > 不给新 token 的话，改完密码自己这张也失效了，表现是「改密码成功，然后整个界面开始报未登录」——正确但难看。 `(P16.9)`
- [ ] **28.** 手机上登录（或另一台电脑）→ 桌面改一次密码 → 手机刷新，应当**立刻被踢出**（不是等到 7 天有效期结束）。新密码能登录，旧密码不能。
  > 这批之前根本没有改密码接口，而 token 有 7 天有效期、服务端不存状态——「我怀疑 token 泄露了」这件事无法处理，你能做的只有等它过期。 `(P16.9)`
- [ ] **29.** 设置 → **账号 → 恢复码**：点「显示」看到分组形态（`a3f9c1e0-8b7d4526-…`），点「复制」能粘出来。**先抄下来**，下面三条要用。
  > 老库（这个功能之前建的）这里会是「还没有恢复码」+ 一个生成按钮，点一下生成再抄。迁移里不自动塞随机值——那样用户从不知道它存在，而这个码只有抄下来才有意义。 `(P17.2)`
- [ ] **30.** 退出登录 → 登录页点「忘记密码」→ 填刚抄的恢复码 + 新密码（两次）→ 成功后**先摆出一个新的恢复码**让你抄，点「我记下了」才进应用。新密码能登，旧密码不能，其他设备被踢下线。
  > 旧码是一次性的、已经用掉了。不当场摆出新的，用户手里那张纸就悄悄过期了，而他要到下一次忘密码时才发现。 `(P17.2)`
- [ ] **31.** 拿**刚用过的那个旧码**再重置一次 → 应被拒。再拿一个乱填的 32 位 hex 试 → 也被拒，且密码没变、当前登录不受影响。 `(P17.2)`
- [ ] **32.** 连错 5 次以上 → 出 429 让你等几分钟。**等限流过去之后，正确的恢复码仍然有效。**
  > 这一条是刻意的：没有「错 N 次作废」。作废会变成永久锁死向量——攻击者随手猜几次就废掉你唯一的兑回路径，而你正处在「忘了密码」的状态，只能回去改 D1。128 bit 的熵本来就穷举不动，限次只剩副作用。 `(P17.2)`

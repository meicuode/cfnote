## P1 数据导出备份

**背景**:所有笔记只存在 D1 一份,免费额度无长期自动备份,数据丢失是单用户知识库的最大风险;同时需要数据可迁移性(不被平台锁死)。

**需求**:
- 新增 `GET /api/export`(需认证),导出全部数据为单个 JSON 文件:笔记本、文章(全文)、对话及消息、非敏感设置(排除 `*_api_key` 等敏感项)
- 响应带 `Content-Disposition` 附件头,文件名 `cfnote-export-<日期>.json`
- 设置面板新增「数据备份」区块,一键下载

**验收**:导出文件包含全部文章内容;敏感 Key 不出现在导出文件中;浏览器点击即下载。

**暂不做**:Markdown zip 打包导出、导入恢复(需处理覆盖语义与重新向量化,列入 P5 后续)。

## P2 混合搜索(关键词 + 向量融合)

**背景**:纯向量搜索对精确词(函数名、专有名词、短词)召回差。

**技术选型说明**:不用 SQLite FTS5——默认分词器不切中文,trigram 分词要求查询≥3字符(中文双字词大量存在);单用户规模(数百至数千篇)下 `LIKE '%词%'` 全扫描完全够用,且对中文子串匹配天然正确、零表结构变更、无同步/回填问题。

**需求**:
- `POST /api/search` 内部改为两路召回:现有向量检索 + 关键词检索(查询按空白切词,`title LIKE / content LIKE`,标题命中权重高于正文)
- 两路结果按 RRF(Reciprocal Rank Fusion,k=60)融合排序,按文章去重
- 仅关键词命中的文章,摘录首个命中位置前后文本作为 `chunk_text` 片段
- 响应结构保持兼容(前端无需改动),新增可选 `match` 字段标注命中方式(vector/keyword/both)

**验收**:搜索文章中确切出现过的短词(如两字中文词、英文标识符)能召回;原语义搜索行为不劣化;LIKE 特殊字符(% _)正确转义。

## P3 AI 对话流式输出(SSE)

**背景**:70B 模型回答需数秒,当前整段等待白屏,体感差。

**需求**:
- `POST /api/conversations/:id/messages` 支持流式:请求体带 `stream: true` 时返回 `text/event-stream`
- 自定义 SSE 事件协议:`{"type":"delta","text":...}` 增量、`{"type":"status","message":...}`(联网搜索中间态)、`{"type":"done", ...完整消息负载(与现 JSON 响应一致)}`、`{"type":"error","message":...}`
- **联网搜索门控**:第一次 LLM 调用先在服务端缓冲,确认开头不是 `[WEB_SEARCH]` 标记后才开始向客户端转发增量;若是标记则完整消费后走搜索分支(发 status 事件),第二次总结调用的增量可直通
- 推理模型(DeepSeek R1/QwQ)不流式(`<think>` 标签需完整清理),服务端自动回退为现有 JSON 响应;前端按响应 Content-Type 自适应
- 消息落库、标题更新、用量埋点在流结束后通过 `waitUntil` 完成,行为与现状一致
- 前端 AI 面板逐字渲染增量,完成后以 done 负载中的正式消息对象替换

**验收**:通用模型对话逐字出现;推理模型行为不变;联网搜索流程不受影响;刷新后历史消息完整(落库无丢失)。
